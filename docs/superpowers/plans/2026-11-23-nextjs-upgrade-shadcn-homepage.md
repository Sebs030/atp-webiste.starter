# Next.js Upgrade + shadcn/ui Small Business Homepage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade this scaffold to Next.js 16.4.6 / React 19 / Tailwind v4, install shadcn/ui, and replace the default page with a production-ready generic small-business homepage template deployable on Azure Static Web Apps.

**Architecture:** Upgrade in two phases — first stabilize the dependency stack (Next.js, React, Tailwind v4, shadcn/ui init), then build seven isolated section components composed in `app/page.tsx`. All sections are React Server Components by default; only the contact form is a Client Component for `react-hook-form`.

**Tech Stack:** Next.js 16.4.6, React 19, Tailwind CSS v4, shadcn/ui (latest, New York style), react-hook-form, zod, lucide-react

**Spec:** Conversation context (2026-11-23) — upgrade + small business homepage template

## Global Constraints

- Next.js: exactly `16.4.6`
- React / React-DOM: `^19` (peer dep of Next.js 16)
- Tailwind CSS: `^4` — CSS-first config, **no `tailwind.config.ts`**
- postcss: `@tailwindcss/postcss` replaces separate `tailwindcss` + `autoprefixer` plugins
- shadcn/ui: `npx shadcn@latest` — style **New York**, base color **Slate**, CSS variables **yes**
- Node.js engine floor: `18.17.1` (keep or bump if Next.js 16 demands higher)
- Target: Azure Static Web Apps hybrid mode — do not add `output: "standalone"` or `staticwebapp.config.json` unless Azure deploy breaks
- No dark mode toggle shipped (CSS `prefers-color-scheme` media is kept as a passive opt-in by shadcn's globals)
- All section text is placeholder copy; variable names make intent clear for customization

## Review Focus

1. **Tailwind v4 CSS variable scope** — if `:root` variables are missing or misspelled, all shadcn/ui components render unstyled. Task 2 must visually confirm a Button renders with correct Slate styling before moving on.
2. **shadcn/ui `components.json` path aliases** — if `@/components` or `@/lib` don't resolve, every component import fails at build time. Task 2 must run `next build` successfully.
3. **Mobile nav Sheet close on navigate** — clicking a nav link on mobile must close the Sheet drawer. Task 3 must test this manually at ≤ 768px viewport by clicking each nav link.
4. **Contact form submit with no server action** — form must degrade gracefully (show a success message, not throw). Task 6 wires a mock `onSubmit` that sets `submitted` state; no real API call is made.
5. **`next/image` missing dimensions** — Next.js throws a build error for `<Image>` without `width`/`height` or `fill`. The About section placeholder uses a plain `<div>`, not `<Image>`, to avoid this constraint.

Zod schema (define at module scope):
```ts
const schema = z.object({
  name: z.string().min(2, "Name must be at least 2 characters"),
  email: z.string().email("Please enter a valid email"),
  subject: z.string().min(3, "Subject must be at least 3 characters"),
  message: z.string().min(10, "Message must be at least 10 characters"),
});
type FormValues = z.infer<typeof schema>;
```

Component state: `const [submitted, setSubmitted] = useState(false)`

`useForm<FormValues>({ resolver: zodResolver(schema) })`

`onSubmit(values: FormValues)`: `console.log(values)` then `setSubmitted(true)`
